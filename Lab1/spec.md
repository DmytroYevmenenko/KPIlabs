# Специфікація вимог та моделі даних — Scooter Rental Service

## Намір
Спроектувати логічну модель даних для сервісу оренди електросамокатів, яка забезпечує пошук станцій, вибір транспорту, фіксацію поїздок користувачами та розрахунок їхньої вартості.

## Сутності та атрибути
1. **USER (Користувач)**: `id` (string), `name` (string), `email` (string)
2. **STATION (Паркувальна станція)**: `id` (string), `location_name` (string), `capacity` (int)
3. **SCOOTER (Самокат)**: `id` (string), `model` (string), `battery_level` (int), `station_id` (string, FK, nullable)
4. **RENTAL (Поїздка)**: `id` (string), `user_id` (string, FK), `scooter_id` (string, FK), `start_time` (datetime), `end_time` (datetime, nullable), `total_cost` (decimal)

## Зв'язки
* `STATION` ||--o{ `SCOOTER` : hosts (Станція і Самокат — один-до-багатьох; `station_id` може бути нульовим, якщо самокат перебуває в дорозі)
* `USER` ||--o{ `RENTAL` : makes (Користувач і Поїздка — один-до-багатьох)
* `SCOOTER` ||--o{ `RENTAL` : used_in (Самокат і Поїздка — один-до-багатьох)

## Критерії прийняття
* Всі ідентифікатори (`id` та зовнішні ключі) мають єдиний тип `string`.
* Нормалізація 3NF: відсутні транзитивні чи часткові залежності.
* Прямий зв'язок M:N між користувачем і самокатом відхилено на користь асоціативної сутності `RENTAL`, оскільки поїздка має власні атрибути часу та вартості.
* Рівень заряду акумулятора `battery_level` логічно обмежений межами від 0 до 100.s
